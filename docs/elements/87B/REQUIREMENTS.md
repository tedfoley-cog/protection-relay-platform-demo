# 87B busbar differential — requirements

Source: customer requirement `PCE-REQ-2026-087 rev B`
(`requirements/customer/87B-customer-requirement.md`), decomposed per
`docs/standards/REQUIREMENTS_CONVENTION.md`. Platform-implied rows cite
`docs/platform/*.md` and `docs/platform/OPEN_QUESTIONS.md` (Qn).

Base used for every per-unit figure below while REQ-87B-007 is BLOCKED:
Ib = 20 MVA / (sqrt(3) x 12.47 kV) = 926.0 A primary (prototype assumption A1).

Status key: `agreed` accepted as written · `implemented` code + test present on
this branch · `BLOCKED` needs a customer answer; the prototype proceeds under
the numbered assumption in section 2, which is not a default.

## 2. BLOCKED rows — questions for the customer and prototype assumptions

Every assumption below is written down so the prototype can be built and
measured; none of them is a default and each row stays BLOCKED until answered.

| Row | Question | Prototype assumption |
|---|---|---|
| REQ-87B-005 | Above the breakpoint, is the operate threshold S1 x BP + S2 x (Ir - BP) (continuous at the breakpoint) or S2 x Ir (through the origin, with a step at the breakpoint)? | A2: continuous at the breakpoint. |
| REQ-87B-007 | Which base is intended: bus rating (20 MVA at 12.47 kV -> 926 A), the largest bay CT primary (2000 A), or something else? The pickup range "0.05-2.0 pu of the largest CT primary" and "all quantities in pu of the bus rating" cannot both hold. Must the base follow the CT table automatically or be a setting? | A1: one base, Ib = `87B_BASE_MVA` (default 20 MVA) at sqrt(3) x `VT_V_LN_NOMINAL`, for settings, characteristic and actual values. |
| REQ-87B-012 | Defaults S1 = 60 %, S2 = 25 % make the second slope flatter than the first. Are the defaults swapped (S1 = 25 %, S2 = 60 %), or is "slope 1" meant to be the high-restraint slope? Shall the relay enforce S2 >= S1? | A3: enforce S2 >= S1 (R-87B-005); prototype defaults S1 = 25 %, S2 = 60 %. |
| REQ-87B-013 | Is "within one cycle" measured from fault inception at the relay terminals to the trip contact, or from the moment the measured differential exceeds 2 x pickup? The platform's full-cycle DFT gives a decision ~18.8 ms after inception; a sub-cycle target needs a half-cycle or sample-based algorithm (new DSP, new budget evidence). Is 1.25 cycles from inception acceptable? | A4: report the measured inception-to-operate time; no new DSP in this change. |
| REQ-87B-014 | Please supply CT class, knee voltage and burden for each bay (or confirm the 20 x figure assumes CTs that do not saturate). The test set models ideal CTs and a 20 MVA source (max through fault ~4.8 kA, i.e. 8 x the bay-3 CT), so 20 x with saturation cannot be demonstrated. | A5: ideal CTs; security shown by scenario + seeded sweep and stated as a limitation. |
| REQ-87B-017 | Seal-in until what: manual 86B lockout reset (platform behaviour), breaker-open and current-gone (as TRIP1), or element drop-out plus a minimum dwell? | A6: TRIPB (86B) latched until `ied_reset_lockout()`; TRIP1 follows the existing release rule; the 87B operate operand itself follows Id. |
| REQ-87B-018 | (a) Define "under load": minimum restraint (e.g. Ir >= 0.1 pu) or minimum per-bay current? (b) What is the alarm output: SOE event, DNP3 point, a physical contact (none exists on the platform)? (c) An open CT under 320 A load gives Id = 0.35 pu, above pickup and (with 25 % slope) above the characteristic, so 87B would trip before a 3 s alarm. Is an instantaneous low-set CTS block required, or is reliance on the hardware CT supervision (`invalid_mask`) accepted? | A7: "under load" = Ir >= 0.1 pu and Id below `87B_PICKUP`; alarm = SOE event + operand + DNP3 binary; no instantaneous block. |
| REQ-87B-020 | Bay 5 needs 3 more analogue channels than the 16-channel acquisition provides. Is this a new hardware variant (out of scope here), and should the 87B settings reserve `87B_BAY5_*` keys now? | A8: not implemented; code loops over `IED_NUM_BAYS` so a 5-bay build inherits the element. |
| REQ-87B-021 | Confirm an out-of-zone bay is removed from both the differential and the restraint sums, that its CT validity no longer blocks 87B, and state what protects the bay while transferred (the relay has one zone). | A9: as stated in the row. |
| REQ-87B-023 | Is bay 4 energised and connected to the bus at the pilot site while its CTs are not wired? If yes, 87B cannot be in service (either it is blocked by the invalid bay, or bay-4 load appears as a standing differential if bay 4 is set out of zone). If bay 4 is de-energised, may it be commissioned with `87B_BAY4_IN_ZONE = NO`? | A10: bay 4 in zone and `CT_CONNECTED = NO` -> element blocked; nothing is substituted. |
| REQ-87B-024 | Should `87B_FUNCTION` default to Disabled until the commissioning tests pass (bay-4 CTs are not wired at the pilot site)? Should disabling clear a standing 87B-initiated 86B lockout? | A11: default Enabled as written; disabling resets the element but not the lockout. |
| REQ-87B-028 | Is one cycle of arming after power-up or reset acceptable (platform default), or is a longer delay required for energising onto a fault? | A12: one cycle (Q6 default). |
| REQ-87B-029 | On a settings write, shall a running CTS timer restart (platform default: reset all element state), or hold? | A13: reset on finalize (Q5 default). |
